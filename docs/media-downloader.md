# Media Downloader

## MVP Scope

The first implementation supports public YouTube single-video URLs only:

- Analyze metadata through `POST /api/media/analyze`
- Show title, thumbnail, duration, and available MP4/MP3 presets
- Download MP4 video or MP3 audio through `POST /api/media/download`
- Run only in local Node.js runtime with `yt-dlp`, `ffmpeg`, and `ffprobe`

It does not support playlists, private videos, paid videos, DRM, login, cookies,
session reuse, or access-right bypassing.

## API Contract

### `POST /api/media/analyze`

Request:

```json
{
  "url": "https://www.youtube.com/watch?v=..."
}
```

Success response:

```ts
type MediaInfo = {
  platform: "youtube";
  originalUrl: string;
  title: string;
  thumbnail?: string;
  durationSeconds?: number;
  formats: MediaFormat[];
};
```

Analyze returns MP4 and MP3 preset formats when compatible source formats are
available. Video presets are `video-mp4-360`, `video-mp4-720`, and
`video-mp4-1080`. Audio presets are `audio-mp3-128` and `audio-mp3-192`.

### `POST /api/media/download`

Request:

```json
{
  "url": "https://www.youtube.com/watch?v=...",
  "type": "video",
  "formatId": "video-mp4-720"
}
```

`type` must match the `formatId` family. The optional `quality` field is
accepted for compatibility but is not used by the current local adapter.

Success response:

- Binary media file body
- `Content-Type`: `video/mp4` or `audio/mpeg`
- `Content-Disposition`: sanitized server-generated attachment filename
- `Cache-Control`: `no-store`

Error response:

```ts
type MediaErrorResponse = {
  code: MediaErrorCode;
  message: string;
};
```

Defined error codes are `INVALID_URL`, `UNSUPPORTED_PLATFORM`,
`MEDIA_NOT_FOUND`, `MEDIA_UNAVAILABLE`, `FORMAT_NOT_AVAILABLE`,
`MEDIA_TOOL_UNAVAILABLE`, `DOWNLOAD_FAILED`, `FFMPEG_FAILED`, `TIMEOUT`, and
`UNKNOWN`.

## Local Requirements

Install the media tools and make them available on PATH, or point the app at
their absolute paths:

```env
YTDLP_PATH=yt-dlp
FFMPEG_PATH=ffmpeg
FFPROBE_PATH=ffprobe
MEDIA_ANALYZE_TIMEOUT_MS=45000
MEDIA_DOWNLOAD_TIMEOUT_MS=180000
MEDIA_MAX_OUTPUT_BYTES=367001600
```

Default fallback values are the same command names and numeric limits shown
above. `MEDIA_MAX_OUTPUT_BYTES` defaults to 350 MiB.

Before analyze and download work starts, the API performs lightweight runtime
readiness checks. Analyze requires only `yt-dlp`:

- `yt-dlp --version`

Download additionally requires both FFmpeg tools:

- `ffmpeg -version`
- `ffprobe -version`

Missing or misconfigured local tools return the stable
`MEDIA_TOOL_UNAVAILABLE` error instead of exposing raw process errors to the
browser. The Analyze response identifies `yt-dlp` and the download response
identifies the FFmpeg tools when those checks fail.

## File Lifecycle

The current local MVP keeps file handling intentionally small:

```text
request
  -> validate URL and format
  -> create random OS temp job directory
  -> run yt-dlp with a fixed output template
  -> reject empty or oversized output
  -> read the finished file into the response
  -> remove the job directory in finally
```

Video downloads use a height-capped selector and merge/remux output to MP4.
Audio downloads extract the best available audio and transcode to MP3 at the
requested bitrate.

The API still buffers the finished media file in memory before returning it.
That is acceptable for the local MVP limit, but it is not the target production
shape for large files or concurrent downloads.

## Security Boundaries

- Only HTTPS URLs are accepted.
- MVP host allowlist is `youtube.com`, `www.youtube.com`, and `youtu.be`.
- YouTube playlist-style URLs are rejected; downloads also pass `--no-playlist`.
- localhost, loopback, private IPv4 ranges, carrier-grade NAT, link-local
  ranges, multicast/reserved IPv4 ranges, and local IPv6 addresses are rejected
  before extraction.
- User input is never concatenated into a shell command; child processes use
  `spawn(command, args, { shell: false })`.
- User-facing errors are mapped to stable codes/messages instead of raw stderr.
- Filenames are sanitized and generated by the server, not taken from URL input.
- YouTube thumbnail hosts are explicitly listed in CSP and Next Image settings.

The MVP does not perform DNS resolution or redirect-chain private-network
inspection because the YouTube host allowlist is intentionally narrow. If the
allowlist is expanded, that check should be added before production use.

## Future Production Architecture

Vercel/Next.js API routes should not remain responsible for long-running media
jobs or large file proxying in production. The planned migration path is:

```text
Next.js UI
  -> Media API
  -> Queue
  -> Media Worker
  -> yt-dlp / FFmpeg
  -> Object Storage
  -> Signed Download URL
```

The existing feature keeps domain types, validation, error mapping, and adapter
interfaces separate so the local process implementation can be replaced by a
worker-backed implementation without rewriting the UI contract.

## Playlist Foundation Notes

Playlist support is intentionally not implemented in the current downloader.
The next playlist PR should start with URL detection and analyze-only behavior,
while preserving the existing single-video flow and `--no-playlist` download
guard.

Recommended minimum model split:

- Keep `MediaInfo` for a single downloadable video.
- Add a separate playlist analyze response instead of overloading `MediaInfo`.
- Represent playlist items with stable `id`, `title`, optional `duration`, and
  original item URL.
- Keep the first MVP download path sequential and per-item, not a blind batch
  loop hidden behind one request.
- Track per-item status as `idle`, `queued`, `downloading`, `completed`, or
  `failed` so retry can be added without redesigning the UI.

Do not add Redis, a queue, object storage, zip packaging, or platform adapters
as part of playlist URL detection. Those belong to later production or platform
expansion steps.
