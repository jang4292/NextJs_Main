# 2048

> 인덱스: [README.md](./README.md)

## 1. 기획서 / 분류

### 개요
4×4 보드에서 같은 숫자 타일을 합쳐 2048 타일을 만드는 것이 목표인 퍼즐 게임. 매 이동마다 빈 칸에 새 타일(2 또는 4)이 하나 생성되고, 인접한 같은 숫자 타일이 합쳐지면 점수가 오른다. 더 이상 이동할 수 없으면 게임 오버, 2048 타일을 만들면 승리.

### 코드 위치
- 도메인: `features/2048/domain/entities`(Board, Direction, GameState), `domain/rules`(moveRowLeft, boardStatus, lines), `domain/services`(moveBoard, spawnTile)
- 애플리케이션: `features/2048/application/use-cases`(startNewGame, makeMove, reconcileTiles)
- 프레젠테이션: `features/2048/presentation`(Game2048.tsx, Board2048View, Tile2048View, ScoreBar, GameOverBanner, WinToast) + hooks(`useGame2048`, `useBestScore`, `tileIdGenerator`) + interaction(`useSwipeInput`, `useKeyboardInput`, `swipeGeometry`)
- 라우트: `app/games/2048/page.tsx` (동적 임포트, `ssr: false`) + `Game2048Client.tsx`

### 기능 분류

**구현 완료**
- 4×4 보드에서의 상하좌우 이동/병합 (`makeMove`, `moveRowLeft`)
- 점수 추적 및 최고 점수 저장 (`localStorage` 키 `portfolio.game2048.bestScore`, `useBestScore.ts`, `useSyncExternalStore` 기반으로 SSR-safe하게 구현되어 서버 스냅샷은 0)
- 승리 토스트(`WinToast`) / 게임오버 배너(`GameOverBanner`)
- 타일 생성·병합 애니메이션 (타일 id 재조정 방식, `reconcileTiles.ts`)
- 키보드 입력(`useKeyboardInput`) + 스와이프 입력(`useSwipeInput`) 동시 지원

**부분 구현 (도메인은 있으나 UI로 노출되지 않음)**
- 보드 크기: `createEmptyBoard(size)`가 파라미터화되어 있어 4×4 외 크기도 도메인상 생성 가능하지만, `BOARD_SIZE = 4` 상수로 고정되어 있고 UI에서 크기를 바꿀 방법이 없음.

**미구현**
- Undo: `useGame2048.ts`의 리듀서 액션은 `MOVE` / `RESTART` / `CLEAR_TILE_FLAGS` 세 가지뿐이며 이전 상태로 되돌리는 액션이 없음.
- 난이도/설정 화면, 게임 일시정지 기능 없음.

## 2. 개선 방향

기존 구현의 완성도를 높이는 항목:
- 스와이프 입력의 판정 임계값(`swipeGeometry.ts`)이 실제 기기별 터치 감도에 잘 맞는지 검증 및 튜닝
- 타일 병합 애니메이션 중 빠르게 연속 입력했을 때(더블 스와이프 등) 상태 불일치가 없는지 점검
- 게임오버/승리 배너의 접근성(스크린리더 안내, 포커스 이동) 보완
- 최고 점수가 기기/브라우저 로컬에만 저장되므로, 저장 실패(시크릿 모드 등) 시의 폴백 동작을 명시적으로 다루는지 확인

## 3. 개발 방향

기술/아키텍처 관점 로드맵:
- 테스트 파일 9개로 세 게임 중 가장 적은 편 — `moveBoard`/`spawnTile` 등 도메인 서비스와 `reconcileTiles`(애니메이션 상태 재조정)의 엣지 케이스 테스트 보강
- `app/games/2048/page.tsx`의 `dynamic(..., { ssr: false })` 패턴이 솔리테어·마인스위퍼와 동일하게 반복되고 있어, 공통 "클라이언트 전용 게임 로더" 유틸/HOC로 추출 검토 (자세한 내용은 [README.md](./README.md)의 공통 관찰 사항 참고)
- `createEmptyBoard(size)`가 이미 파라미터화되어 있으므로, 보드 크기 확장 시 도메인 레이어 변경 없이 프레젠테이션 레이어만 손대면 되는 구조를 유지

## 4. 기능 개편 방향

- **Undo 기능 추가**: 리듀서에 `UNDO` 액션과 이전 상태 스택(1~수 회 제한 권장)을 추가. `makeMove`가 순수 함수이므로 상태 스냅샷을 쌓아두는 방식으로 비교적 단순하게 구현 가능.
- **보드 크기 선택 UI**: 도메인이 이미 지원하는 `createEmptyBoard(size)`를 활용해 3×3/5×5 등 난이도 변형 추가.
- **게임 허브 페이지**: `app/games/page.tsx`가 아직 없어 2048 진입점이 다른 게임과 함께 노출되지 않음 — 세 게임 공통 이슈이므로 [README.md](./README.md) 참고.
